# RC61.2 — Sync & Empty-State Orchestration

Date: 2026-08-17
Status: CLOSED

## Closeout objective

RC61.2 closes the Motion & Microinteractions rail by making synchronization,
success/error and empty/loading transitions semantic rather than purely visual.

The source of truth remains the existing static UI text, status attributes and
accessible controls. Motion is supplemental feedback only.

## Semantic orchestration

The motion controller now recognizes these semantic states:

- synchronization banner;
- success action state;
- error action state;
- empty state;
- loading/skeleton state.

Each state has a signature built from:

- semantic kind;
- visible product copy;
- data-status;
- aria-busy;
- visibility.

The controller primes states that already exist when it mounts. They are not
animated merely because the controller was attached.

After that, a node animates only when its semantic signature changes. Repeated
MutationObserver records for an identical state do not replay motion.

## Empty/loading transitions

Empty/loading feedback uses entrance motion only when the state becomes a new
visible semantic state.

Hidden states do not animate.

No content is generated by the motion layer. Empty/loading copy remains normal
DOM content and remains fully available with JavaScript motion disabled.

## Synchronization transitions

Synchronization feedback is driven by existing `.m26-sync-banner` state and
copy. A pending → clean/error change produces one status transition.

The motion layer does not write sync status, does not acknowledge commands and
does not alter retry/queue behavior.

## Reduced motion

`prefers-reduced-motion: reduce` remains authoritative.

The RC61.1 CSS fail-safe is preserved and the JavaScript controller continues
to skip WAAPI when reduced motion is active.

## Engine closeout

Native same-origin WAAPI remains sufficient for the current interaction set.

Release decision:

`MOTION_LIBRARY_RELEASE_DECISION=DEFERRED_NATIVE_WAAPI_SUFFICIENT_RC61`

Motion library and AutoAnimate are not added.

## Focused-test compatibility

The first focused RC61.2 run reported two test-only failures for empty states.

Production uses the browser-native `Element.matches()` API with selector lists
such as `.m26-empty-copy,[data-empty-state]`. The test double initially treated
the entire selector list as one literal string, unlike a real DOM element.

The mock now evaluates comma-separated selector alternatives. No production
motion behavior was changed by this compatibility patch.
